# InfraRadar

**Анализ рисков Active Directory на реальных данных тестового домена.** Приложение читает объекты infraradar.test, объясняет находки, показывает пути административных прав и сохраняет историю сканирований. Анализ и рекомендации **не меняют AD**.

> **Коротко:** разработчик запускает React и FastAPI у себя. Локальный backend получает read-only снимок AD через защищённый Gateway, сам выполняет правила и scoring, затем сохраняет результат в локальную SQLite. Tailscale и доступ к контроллеру домена на компьютере разработчика не нужны.

## Быстрый запуск

Нужны **Python 3.12+**, **Node.js 20+** и личный токен AD Gateway от администратора проекта.

~~~bash
git clone https://github.com/ab1lmns/kmg_hack.git
cd kmg_hack
cp backend/.env.example backend/.env
chmod 600 backend/.env
~~~

В файле **backend/.env** заполните персональный токен; адрес Gateway уже указан в примере:

~~~dotenv
AD_SOURCE=gateway
AD_GATEWAY_URL=https://identity-risk.46.101.134.38.sslip.io
AD_GATEWAY_TOKEN=<личный_токен>
~~~

~~~bash
./run
~~~

Откройте **http://127.0.0.1:5173** и нажмите «Запустить анализ». Скрипт создаёт Python venv, устанавливает зависимости при необходимости и запускает локальные FastAPI и Vite. Первый сбор может занять несколько десятков секунд. Без токена живой анализ через Gateway недоступен.

**Не отправляйте backend/.env другому разработчику.** Каждому нужен собственный отзывной токен. LDAP-пароль, ключ чтения Event Log и другие серверные секреты остаются на DigitalOcean. Подробности выдачи токенов и устранения ошибок — в [инструкции для разработчика](docs/GATEWAY_DEV.md).

## Что есть в приложении

| Раздел | Что показывает |
| --- | --- |
| **Обзор** | Оценку безопасности домена, распределение находок, самые рискованные аккаунты и динамику сканирований. |
| **Карта рисков** | Связи аккаунтов, групп и находок; реальные пути членства отличены от связей навигации. |
| **Риски** | Причину, подтверждающие данные и рекомендацию для каждого сработавшего правила. |
| **Аккаунты** | Состояние пользователей и сервисных учётных записей, права, активность и персональный Risk Score. |
| **Компьютеры** | Объекты компьютеров AD и их проверки. |
| **Политика домена** | Парольную политику, FGPP и найденные отклонения. |
| **Аутентификация** | Нормализованные события Security Event Log и сигналы возможного brute force или password spray. |
| **История** | Сохранённые анализы и сравнение результатов. |
| **Подключение** | Состояние источников, сведения о домене/DC и параметры анализа. |

Из результатов можно выгрузить **CSV**. Файл содержит UTF-8 BOM и разделитель `;`, чтобы русские поля корректно открывались в Excel. Кнопка «Спросить ИИ» и план исправления находки работают при наличии `OPENAI_API_KEY` в `backend/.env`; это необязательная функция. Вопрос и данные анализа отправляются из backend в OpenAI API, поэтому не вводите в чат секреты. Без ключа сканирование и основные разделы работают.

## Как устроено подключение

~~~text
React в браузере
       │ /api через локальный Vite
       ▼
Локальный FastAPI ──► локальные правила, Risk Score, SQLite, CSV
       │ HTTPS + персональный токен
       ▼
AD Gateway на DigitalOcean ──► нормализованный read-only снимок
       │ приватный Tailscale
       ▼
Windows Server / Active Directory / Security Event Log
~~~

Gateway собирает пользователей, группы и вложенность, компьютеры, парольную политику и FGPP, SPN, атрибуты делегирования, оценку интерактивного входа на DC и события Security Event Log. Он **не выполняет Risk Engine и не хранит историю сканов разработчика**. Изменение локального backend/app/analysis.py применяется после перезапуска локального backend и нового анализа; развёртывание Gateway для этого не требуется. Gateway не принимает произвольные LDAP-запросы и не предоставляет операций записи в AD.

Для серверного/лабораторного режима сохранён AD_SOURCE=ldap_direct. Его LDAP и Event Log credentials должны находиться только в закрытом серверном окружении. Приватный frontend через Tailscale остаётся резервным административным вариантом; [схема командного доступа](docs/TEAM_ACCESS.md). Публичное размещение общего frontend описано отдельно в [проверке безопасности Vercel](docs/VERCEL_SECURITY.md) и не заменяет локальный backend разработчика.

## Как читать результаты

- **AD Security Score: 100 = лучше.** Это сводная оценка найденных рисков, а не гарантия защищённости.
- **Account Risk Score: 100 = хуже.** Основан на severity сработавших правил и дополнительных находках; [точная формула](docs/RISK_SCORING.md).
- **«Вход не наблюдался» ≠ «неактивен».** У нового аккаунта без записи о входе правило неактивности сработает только после заданного срока, сейчас по умолчанию **90 дней**. lastLogonTimestamp приблизителен, а точный lastLogon относится к конкретному DC.
- **pass, partial, not_evaluated и error различаются.** Частичный журнал событий или недоступный источник нельзя трактовать как доказанное отсутствие атак.
- **Находка указывает на проверяемый риск, а не на подтверждённый взлом.** Рекомендации и ИИ-планы не выполняют действия в AD автоматически.

**Снимок от 25 сентября 2026 года, 07:28 UTC:** 43 аккаунта, 41 находка, AD Security Score 75/100; один аккаунт Critical, неактивных по порогу 90 дней — 0. LDAP, FGPP, компьютеры и права интерактивного входа доступны; Security Event Log имеет статус partial. Эти числа меняются после новых анализов и не должны использоваться как постоянная характеристика стенда. Текущие цифры смотрите в приложении или через GET /api/dashboard.

Тестовая OU — OU=InfraRadarLab,DC=infraradar,DC=test. Она содержит вымышленных сотрудников, отдельные adm.*, сервисные svc_* и технические reader-аккаунты. Даты создания и входа в AD не подделывались. Положительные случаи некоторых правил проверены unit-тестами и могут отсутствовать в текущем live-снимке.

## Разработка и проверки

Скрипт **./run** оставляет backend на 127.0.0.1:8000, frontend на 127.0.0.1:5173. Если хотите запускать процессы отдельно:

~~~bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
~~~

В другом терминале:

~~~bash
cd frontend
npm ci
npm run dev
~~~

Проверка без изменения AD:

~~~bash
cd backend
.venv/bin/python -m unittest discover -s tests -v
cd ../frontend
node --test src/*.test.js
npm run build
~~~

RUN_LDAP_SMOKE=1 включает прямой LDAP smoke-тест только в среде с доступом к DC и соответствующими учётными данными; обычному разработчику через Gateway он не нужен. Актуальные ограничения, включая неполную проверку некоторых вложенных путей привилегий и параметров FGPP, перечислены в [последнем аудите](docs/PRE_PUSH_REVIEW_2026-09-25.md). Исторические результаты live-проверок — в [финальном аудите](docs/FINAL_AUDIT.md) и [матрице ТЗ](docs/TZ_COMPLIANCE.md); их числа относятся к датам конкретных сканов.

# Identity Risk Analyzer — демонстрация за 3–4 минуты

> **Проверено 2026-09-25:** 42 lab аккаунта (26 обычных сотрудников), 39 находок, Security Score 75. FGPP назначена одному lab пользователю; обычный scan оценивает интерактивные права DC. Перед показом сверяйте значения с [актуальным аудитом](TZ_AUDIT_CURRENT.md).

## Подготовка

Запустите backend на `127.0.0.1:8000`, откройте этот адрес и убедитесь, что Tailscale подключён. В `backend/.env` должен быть настроен `ir-ldap-reader@infraradar.test`; пароль не показывайте. Источник в верхнем меню — **Active Directory**. Сценарий использует реальные данные тестового OU и не меняет AD.

1. **0:00–0:25 — задача.** «У администратора много учётных записей и групп; вручную трудно заметить рискованные сочетания. Analyzer собирает факты из AD и объясняет каждый риск».
2. **0:25–0:50 — подключение.** Откройте «Подключение»: `infraradar.test`, DC `100.93.42.103`, учётная запись чтения, режим «Только чтение». Нажмите «Проверить соединение» и покажите число пользователей и групп. Не открывайте `.env`.
3. **0:50–1:15 — scan.** Нажмите «Запустить анализ». Покажите статус чтения AD, затем длительность, 42 lab-аккаунта, 57 групп и число находок. Источник последнего scan должен быть Active Directory, не демо.
4. **1:15–1:45 — обзор.** Объясните: AD Security Score выше — лучше; Risk Score аккаунта выше — хуже. Покажите Critical/High/Medium/Low, категории, самые рискованные аккаунты.
5. **1:45–2:20 — подтверждённый Critical.** Откройте `adm.a.sadykov`. Покажите прямой путь к `Domain Admins`, severity, причину, «Почему важно», evidence и рекомендацию. Это тестовый аккаунт с реальным членством в доменной административной группе.
6. **2:20–2:45 — вложенный путь.** Откройте `svc_backup`: путь `svc_backup → IR-Service-Ops → IR-Infrastructure → IR-Lab-Admins`. Подчеркните область права: **только `OU=InfraRadarLab`**. Сервисный аккаунт имеет бессрочный пароль; права интерактивного входа на DC проверены как «Проверен», без находок.
7. **2:45–3:05 — поиск и экспорт.** На странице «Риски» выберите Critical, затем группу Service/High, покажите поиск и сортировку. Скачайте CSV: категория, evidence, рекомендация, UTF-8.
8. **3:05–3:25 — динамика.** Запустите повторный scan. Покажите previous → current для Score/Critical/High и число новых/исчезнувших находок. Без изменений в AD дельта должна быть нулевой.
9. **3:25–3:45 — вывод.** Код разделён на collector, правила, хранение, API и UI; другие источники могут добавляться отдельно. Программа ничего не исправляет автоматически. Источник Security Event Log читается отдельным минимально привилегированным reader; сейчас сигналов Password Spray нет.

Перед защитой сверяйте текущие числа с Dashboard: они могут измениться при изменении тестового AD.
